# QEMU/Files

From Gentoo Wiki

[Jump to:navigation](https://wiki.gentoo.org#mw-head)

[Jump to:search](https://wiki.gentoo.org#searchInput)

A complete list of files used by QEMU command.

## Files

### Configuration files

QEMU uses the following files and directories for QEMU configuration:

| Path | Description | 
|---|---|
| /etc/libvirt/qemu.conf | QEMU configuration file | 
| /etc/libvirt/qemu-lockd.conf | QEMU lock files | 
| /etc/libvirt/qemu-sanlock.conf | QEMU SAN lock | 
| /etc/libvirt/qemu/\<domain-name>.xml | Domain XML setting for a virtual machine or container | 
| /etc/libvirt/qemu/autostart/\<domain-name>.xml | Autostart this domain (virtual machine or container) | 
| /etc/libvirt/qemu/networks/\<network-name>.xml | Network XML setting file for a network connection | 
| /etc/libvirt/qemu/networks/autostart/\<network-name>.xml | Autostart this network connection. | 



### Dynamic files

| Path | Description | 
|---|---|
| /var/lib/libvirt/qemu/channel/target/\<domain-name>/\<socket-file> | UNIX-domain sockets used as endpoints for QEMU guest channels. For example, a socket associated with org.qemu.guest\_agent.0 provides the host-side endpoint for communication with the QEMU Guest Agent running inside the guest. Libvirt/virt-manager/virsh uses this file. | 
| /var/cache/libvirt/qemu/capabilities/\<hash-value>.xml | Host OS capabilities cached in XML format. The files describe available machine types, architectures, devices, firmware, and other capabilities discovered by Libvirt. The hash identifies the corresponding QEMU capability set. | 
| /var/lib/libvirt/qemu/checkpoint/ | Persistent Libvirt metadata for QEMU domain checkpoints. Checkpoint definitions stored in XML. Describe the checkpoint hierarchy and associated domain state; checkpoint data itself may reside in the domain's storage volumes. | 
| /var/lib/libvirt/qemu/\<domain-9-XXXX>/ | Holds UNIX sockets, secret/encryption keys, and other transient data for this domain. Per-domain runtime state directory created for a running QEMU domain. The directory name incorporates the domain identifier and name. | 
| /var/lib/libvirt/qemu/dump/ | Memory dumps of QEMU guest generated by Libvirt. Contains virtual machine memory and associated state needed for post-mortem analysis or debugging. | 
| /var/lib/libvirt/qemu/nvram/ | Persistent UEFI variable stores for virtual machines using UEFI firmware. Each NVRAM file preserves guest-specific UEFI variables, such as boot entries and firmware configuration, across VM power cycles. | 
| /var/lib/libvirt/qemu/ram/ | File-backed guest RAM. | 
| /var/lib/libvirt/qemu/save/ | holding directory of hibernation images and its suspended instruction pointer and register sets. Libvirt-managed. A managed-save image contains the saved execution state and guest RAM of a domain so that Libvirt can restore the domain to its previous running state. | 
| /var/lib/libvirt/qemu/snapshot/ | Holding directory of snapshot definitions. Stored as XML. Describes the snapshot, its parent/child relationships, domain state, and associated storage. The directory does not necessarily contain the snapshot data itself; storage snapshots are maintained by the corresponding storage backend. | 



### State files

- /var/run/libvirt/qemu - various UNIX socket and PID files for the libvirtd daemon.
